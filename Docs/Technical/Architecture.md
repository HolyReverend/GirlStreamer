# Current project architecture

Read before Godot work, then open only the files relevant to the task. This is a map of existing code, not a roadmap. Last checked against source: 2026-11-18.

## Runtime and entry point

- Godot 4.7 Standard, GDScript, GL Compatibility; configured viewport and minimum window size: 1024 × 768.
- Engine root: `GirlStreamer/`; all `res://` paths below are relative to it.
- [project.godot](../../GirlStreamer/project.godot) owns the startup scene, display settings, Input Map, renderer, and enabled editor plugins.
- Startup scene: `res://prototype/day/day_cycle.tscn`. Run `res://prototype/prototype_session.tscn` directly for a standalone stream. No autoloads are currently configured.

## Connections and contracts

- `DayState` runs independently of the scene tree. `preview_activity()` projects an action, and `apply_activity()` re-evaluates current eligibility before committing. `preview_launch()` is available in PREPARING and copies condition, mastery level and daily flags. Either STREAMING or SKIPPED closes preparation. See the [Stage 1 model contract](Iteration03/Stage01DayModel.md).
- `DayCycle` mounts a process-disabled stream candidate behind the room. The controller gives layout up to 12 process frames, connects managed completion for the launching day, starts with a fresh launch snapshot, then commits the launch and transfers control. Failure detaches and frees the candidate and restores room focus.
- After the goodbye, a managed FINISHED session hands its frozen results to the active day controller. Settlement uses the frozen donation total and the model applies the evening load. Skip settles with zero stream income and load. The same model yields the clamped sleep preview and commits it once on continue.
- The day results screen owns Enter and continue input. The controller consumes held Enter and duplicate mouse events across the handoff. Continuing disconnects and removes the finished child, keeps its mute preference, clears daily preparation flags and restores room focus with six AP.
- Scene tree: `PrototypeSession` owns SnakeGame, PrototypeHUD, StreamChoice, StreamDirector, ChatFeed, DonationController and StreamAudio. SnakeGame owns Board. HeroWebcam lives in the HUD's WebcamSlot.
- Layout flow: HUD resize signal → session → `SnakeGame.set_board_rect()` → `SnakeBoard`. The first positive layout rectangle enables explicit start.
- Gameplay flow: Input Map → controller → `SnakeState.request_turn()`; physics accumulator → `SnakeState.step()` → copied snapshot → board redraw.
- Feedback flow: Snake notifications → session accounting → canonical event → chat and webcam. Terminal steps enter WAITING_FOR_RETRY before notifying listeners. Final food counts toward the total and the board completion owns the only feedback event. Accepted Snake events carry the authorized step timestamp. Cosmetic cutoff checks use a read-only sample so they cannot split a terminal notification pair.
- The model starts with three cells facing right. It accepts at most one perpendicular turn per tick; reverse, repeated direction, and non-cardinal requests are rejected.
- Walls and retained body cells end the attempt before movement or reward changes. A nongrowing step may enter the tail cell vacated in that same step.
- Session startup configures the Snake warning range and director multiplier from the detached launch snapshot. Standalone startup uses range 0 and multiplier 1.00. Snake refreshes the hint after accepted steering, movement and pending-turn clears. Terminal movement and stopping clear it. Retry inherits the stream range.
- Session state is READY, RUNNING, PAUSED, CLOSING or FINISHED. Only RUNNING spans contribute to gameplay elapsed time. Expiry takes precedence over gameplay actions. Pausing gates gameplay and clears only the buffered Snake turn, preserving the partial physics tick and retry state.
- Space retries while RUNNING and waiting for an attempt. Enter starts or restarts a standalone session from READY/FINISHED and skips CLOSING in either mode. Escape toggles RUNNING/PAUSED. A managed session keeps its launch snapshot and ends at the day summary. A new session resets time, attempts and aggregate counters.
- StreamChoice uses authorized active time for input deadlines and latency. Open choices survive retries and pause. Stream expiry stops the director and cancels the active choice before the results snapshot. Accepted choices route one authored reply and one compatible chat line.
- StreamDirector snapshots tuning at start. Defaults are 20 s to first opening, at least 20 s between successful openings, and at most eight choices. A reserved prepared topic has first priority, including while waiting for retry. It uses one ordinary slot and retains its reservation until admission. Other ordinary and donor questions require a playing attempt. Loss and completion reactions can open while waiting for retry. The donor's identity, amount, source group and text are copied at receipt.
- Normal-preset ordinary and donor openings sample current viewers, scale the existing base window by the captured concentration multiplier and round to the nearest millisecond with a 5000 ms floor. Custom question windows remain fixed. The choice controller preserves the admitted deadline through a pause or Snake retry.
- The session retains copied outcomes and provisional effects. Ordinary question answer rate and mean exclude reactions. Reaction options have fixed style order and a 3 s window, while ordinary questions default to 6 s.
- The session advances audience drift through the authorized event timestamp before applying an effect. Closing flushes the final passive step and freezes the snapshot. The HUD renders group counts, impressions and measured causes. The director and chat sample current viewers only when assigning a new ordinary question window or ambient deadline.
- The announcement adds one viewer per group during audience reset. The HUD shows the opening gain alongside current audience statistics. Frozen results calculate the live change from the actual opening total. The prepared question is validated before session initialization and carries a hint in one numbered reply. The HUD returns to the normal options grid when that choice clears.
- During RUNNING the session advances drift, resolves due choices, samples at most one donation and then ticks the director. Donor answers and expiry affect audience only. The HUD keeps one visible receipt, three queued records and an overflow aggregate. Closing stops sampling and freezes controller totals before the summary.
- The two-second wall-clock closing interval presents a static webcam goodbye and one finish cue. Ordinary and donor question opens share an audio cue. Each committed routed payment requests one donation cue. A newer gameplay cue replaces the prior one. Rendering results has no model or audio side effects.
- Feed cadence, food feedback cooldown and webcam transients advance only with active stream time. Retry preserves chat history and milestone eligibility. Closing retains chat and replaces gameplay expressions with a static goodbye. Restart resets both views.
- Controller tuning is validated and captured at `start()`: dimensions 8–64, base tick interval 0.05–1.00 seconds. After collecting food, the next movement interval is base / (1 + 0.10 × attempt food). Retry and new stream reset the interval. Pause preserves the interval and accumulated partial tick. A fresh RNG per start uses randomized or fixed seed settings. Editing exports during an attempt takes effect at the next attempt start.

## Scope and tooling

- Implemented gameplay covers repeated days with preparation, a streamed or skipped evening, day results and overnight recovery. Streams include Snake, retries, pause, contextual choices, audience, donations, chat and webcam replies. See the [Stage 5 contract](Iteration03/Stage05DayResultsAndNextMorning.md) for settlement and acceptance boundaries.
- `addons/funplay_mcp/` is vendored editor integration, not gameplay code. The enabled entry is [plugin.cfg](../../GirlStreamer/addons/funplay_mcp/plugin.cfg). Its runtime bridge source exists, but no runtime bridge autoload is configured.
- MCP connection: project `.codex/config.toml` → `Codex/Tools/FunplayMCP/launch.mjs` → pinned stdio wrapper → plugin in the running editor. Read [GodotMCP.md](../../Codex/GodotMCP.md) only for connection details or troubleshooting.
- `.godot/` is generated editor/import data. Keep script `.gd.uid` companions and scene/resource references intact; do not use caches as implementation sources.
